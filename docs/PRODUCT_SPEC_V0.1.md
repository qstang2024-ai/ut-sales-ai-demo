## 1. 产品定位

**产品名称**：UT 销售 AI 助手 · 在线演示中心

**一句话定位**：用一个在线演示站点，系统展示销售 AI 助手如何在真实客户对话中自动识别需求、补全画像、推荐话术、创建流程，并持续沉淀销售过程资产。

**使用场景**：
1. 客户汇报演示
2. 内部产品评审
3. 工程实现参照
4. 销售 AI 助手功能规划
5. 在线 URL 分享演示
6. 后续可扩展为基础方案/产品介绍/合作方案多维度展示

**与当前 V4 的关系**：当前 `ut-sales-ai-scenario-demo-v4-bottom-actions.html` 验证了核心交互方向，但它只是单个 HTML 文件。演示中心是它的升级形态——多 Tab、多阶段、配置化、可在线部署。

## 4. 三栏区域详细定义

### 4.1 左侧：场景说明区

**作用**：解释这个场景为什么有价值。

**固定结构**：
1. 场景标题（阶段名称 + 场景名称）
2. 一句话场景描述
3. 销售真实痛点（1-3 条）
4. AI 如何介入（3-5 条）
5. 展示能力（标签式罗列）
6. 业务价值（一句话）

**设计要求**：
- 文案短、产品化、有层次
- 背景与中间、右侧有明显区隔（浅蓝灰色）
- 使用编号、标签、彩色竖线增强层级

### 4.2 中间：前台使用区

**作用**：展示销售正在企微/微信里真实与客户聊天。

**包含元素**：
- 手机外框（max-width 375px）
- 聊天头部（客户名称、来源标签）
- 对话区（客户白色气泡 + 销售微信绿色气泡 #95EC69）
- typing 指示器
- **底部 AI 工具横条**（5 个按钮，按场景点亮）
- 推荐回复区（AI 生成但未发送的话术）
- 输入框
- **bottom sheet 弹层**（覆盖手机区域，可关闭）

**核心交互原则**：
- 聊天框只放真实客户消息和销售消息
- AI 分析、客户画像、流程任务绝不出现在聊天气泡中
- 所有 AI 交互入口放在底部工具横条
- 弹层覆盖手机区域，关闭后回到对话
- 生成给客户看的话术，先进入推荐回复区
- 销售点击"发送"后，才变成绿色销售气泡

### 4.3 右侧：AI 后台逻辑区

**作用**：展示 AI 在后台理解了什么、记录了什么、推动了什么流程。

**保留 4-5 张主卡**：
1. 客户信息收集状态（含完整度进度条）
2. 项目推进状态（P1-P7 阶段芯片）
3. 内部流程状态（已生成/待创建的 checklist）
4. 推荐知识/动作（场景关联的知识卡网格）
5. 下一步建议（可选）

**设计要求**：
- 背景与左中区有明显区分
- 初始 dim 态（半透明 + 灰度），随对话推进逐步点亮
- 点亮时有 pulse 高亮动画
- 不堆十几个工具模块
- 主要点击交互放在中间底部工具条，右侧不承担主要交互

## 5. 底部 AI 工具横条标准

### 5.1 默认 5 个按钮

| 序号 | 按钮 | 图标建议 | 触发条件 |
|---|---|---|---|
| 1 | 客户画像 | 👤 | 对话中提取到客户画像字段 |
| 2 | 需求摘要 | 📋 | 客户表达明确需求 |
| 3 | 产品推荐 | 🎯 | AI 判断可进入产品匹配 |
| 4 | 试菜日程 | 📅 | 客户表达试菜意向 |
| 5 | 下一步 | ➡️ | 阶段完成或需要后续动作 |

注：不同阶段可调整按钮内容，但建议保持 5 个固定槽位以降低认知负担。

### 5.2 状态设计

- **默认（dim）**：灰色背景，文字 muted，不可点击或点击无效
- **点亮（active）**：蓝色/绿色高亮，显示小徽标（如"70%""待创建""已生成"），点击弹出对应 bottom sheet
- **pulse 动画**：点亮瞬间播放脉冲动画吸引注意力

### 5.3 按钮样式

- 横向排列，可左右滑动
- 每按钮约 60-70px 宽，小胶囊形态
- 有图标 + 标签 + 可选徽标
- 固定在手机底部（输入框上方）

## 6. Bottom Sheet 弹层标准

### 6.1 弹层类型

| 类型 | 触发按钮 | 核心内容 |
|---|---|---|
| 客户画像卡 | 客户画像点亮 | KV 字段列表 + 完整度进度条 |
| 需求摘要卡 | 需求摘要点亮 | 已识别需求 + 待确认清单 |
| 产品推荐卡 | 产品推荐点亮 | 推荐产品 + 推荐理由 + 匹配度 |
| ROI 测算卡 | 关联动作触发 | 人工节省 + 回本周期 + 案例对比 |
| 试菜日程卡 | 试菜日程点亮 | 时间/参与人/菜品 + 内部准备清单 |
| 报价信息卡 | 阶段推进触发 | 报价字段确认 + 待补充项 |
| 合同信息卡 | 阶段推进触发 | 合同关键信息 + 开票/付款提醒 |
| 发货流程卡 | 阶段推进触发 | 收货信息 + 交付团队通知 |

### 6.2 弹层交互要求

- 在手机区域内弹出（bottom sheet 样式）
- 半透明遮罩覆盖聊天区
- 顶部有拖拽手柄 + 关闭按钮
- 从底部滑入，可关闭返回对话
- 内部信息结构清晰，操作按钮突出
- 如生成客户可见话术，先进入推荐回复区，不自动发送

## 7. 场景配置化原则

当前 V4 单场景是硬编码 JS 步骤数组。演示中心需要支持 15+ 场景，因此必须配置化：

**每个场景的数据结构**：

```js
{
  id: "p2-profile-auto-complete",
  stageId: "P2",
  stageName: "客户画像与需求洞察",
  title: "社餐客户画像自动补全",
  subtitle: "从一句聊天，自动长出客户画像和销售动作",

  // 左侧面板
  leftPanel: {
    painPoints: [...],
    aiInterventions: [...],
    capabilities: [...],
    businessValue: "..."
  },

  // 聊天脚本（时间线步骤）
  chatScript: [
    { type: "time", text: "10:32", delay: 300 },
    { type: "customer", text: "...", delay: 700 },
    { type: "typing", duration: 1100, delay: 900 },
    { type: "sales", text: "...", delay: 1100 },
    // 工具横条触发
    { type: "tool_active", toolId: "tool-profile", badge: "70%", pulse: true, delay: 1000 },
    // 弹层触发
    { type: "open_overlay", overlayType: "profile", delay: 1200 },
    // 推荐回复
    { type: "show_rec", text: "...", delay: 500 },
    // 自动发送
    { type: "send_rec", delay: 2000 },
    // ... 更多步骤
  ],

  // 右侧面板卡片更新（与步骤绑定或独立触发）
  rightPanelUpdates: {
    "card-profile": { triggerAtStep: 5, fields: {...}, progress: 70 },
    "card-stage": { triggerAtStep: 8, stage: "P3", checks: [0,1] },
    "card-process": { triggerAtStep: 5, checks: [0] },
    "card-knowledge": { triggerAtStep: 10, cards: [...] }
  },

  // 弹层内容
  overlays: {
    profile: { title: "...", fields: {...}, actions: [...] },
    schedule: { title: "...", fields: {...}, checklist: [...], actions: [...] }
  }
}
```

**关键原则**：15 个场景共享同一个 ScenePlayer 引擎和同一套组件，只换数据不换代码。

## 11. 交互原则（强制约束）

后续所有场景开发必须遵守：

1. **聊天框纯净**：只放客户和销售真实消息
2. **AI 分析不插聊天**：客户画像、流程任务、日程草稿绝不出现在聊天气泡中
3. **AI 入口在底部工具横条**：所有复杂信息通过工具按钮→弹层展示
4. **工具按钮按对话步骤点亮**：不在场景开始就全亮
5. **弹层可关闭**：bottom sheet 覆盖手机区域，关闭后回到对话
6. **推荐回复不自动发送**：先生成到推荐区，销售确认后才变成气泡
7. **右侧是后台状态**：不承担主要点击交互，只做信息展示
8. **双层结构可见**：前台销售对话 + 后台 AI 理解和流程推进
